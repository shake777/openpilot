# AA Probe — 안드로이드 오토 헤드유닛 기능 시험 앱

표준형 5W(예: `YGPE.KOR.S5W_M.V039.001.260902`) 같은 헤드유닛이 안드로이드 오토(AA)로
**① 어떤 차량 데이터를 휴대폰에 넘겨주는지**, **② 휴대폰이 보낸 회전 안내(TBT)를 계기판/HUD에
표시하는지**를 한 번에 확인하는 시험용 앱입니다.

차량 CAN에는 아무것도 송신하지 않습니다. 공식 Android for Cars App Library만 사용합니다.

## 1. 설치

1. `dist/aaprobe-0.2.apk`를 휴대폰에 설치합니다(디버그 키 서명, 시험용).
2. 휴대폰에서 **AA Probe** 앱을 열고 **권한 요청**을 눌러 위치·차량 권한을 허용합니다.
3. 안드로이드 오토 **개발자 모드**를 켭니다.
   - 휴대폰 설정 → 안드로이드 오토 → 맨 아래 **버전**을 10번 탭
   - 오른쪽 위 메뉴 → **개발자 설정** → **알 수 없는 출처** 허용
4. 차량에 USB로 연결하면 AA 앱 목록에 **AA Probe**가 나타납니다.
   보이지 않으면 AA 런처 맞춤설정에서 표시를 켜세요.

## 2. 시험 방법(정차 상태에서 시작)

1. AA 화면에서 **AA Probe** 실행 → 화면에 수집 결과가 글자로 표시됩니다.
2. **① 차량 데이터**: 자동으로 수집합니다. 휴대폰이 이미 받는 속도·GPS와 비교해 헤드유닛 값이
   더 나은지(특히 터널 구간 GPS) 확인하는 용도입니다. 항목별 상태가 표시됩니다.
   - `SUCCESS` = 헤드유닛이 값을 넘겨줌
   - `UNIMPLEMENTED` / `UNAVAILABLE` = 헤드유닛이 제공하지 않음
   - `ERROR …` / `UNSUPPORTED host API` = AA 쪽에서 해당 기능 미지원
   - 괄호 안 숫자는 지금까지 받은 업데이트 횟수입니다(주기 확인용).
   - 데이터 수집은 일반 내비 안내에 영향을 주지 않습니다. 실행 후 일반 내비로 돌아가도 앱이 종료되지 않는 한 계속 기록합니다.
     (`lifecycle` 로그와 업데이트 횟수로 뒤에서도 값이 계속 들어오는지 확인할 수 있습니다.)
3. **② TBT → 계기판/HUD (선택)**: 일반 내비가 이미 AA로 TBT를 보내고 있으므로, HUD 표시 여부는
   평소처럼 일반 내비 안내로 먼저 확인하면 됩니다. 가짜 경로 시험은 표시 형식·회전 종류별 차이를
   따로 보고 싶을 때만 씁니다.
   - **TBT 시험**을 누르고 3초 안에 **한번 더: 시작**을 눌러야 시작됩니다.
     안드로이드 오토는 내비 앱 하나만 안내할 수 있어서, 시작하면 **일반 내비 안내가 중단됩니다.**
   - 반대로 일반 내비에서 안내를 다시 시작하면 AA Probe 시험이 자동으로 멈춥니다(`nav_host_stop`).
   - 가짜 경로가 20초마다 다음 안내로 넘어갑니다:
     우회전 → 좌회전 → 직진 → 오른쪽 방향 → 왼쪽 유지 → 유턴 → 목적지
   - 각 안내는 500m에서 0m까지 1초에 25m씩 줄어듭니다.
   - **다음 안내** 버튼으로 바로 넘길 수 있습니다.
   - 이때 **HUD와 계기판에 화살표/거리가 뜨는지** 확인하고, 가능하면 사진이나 영상으로 남겨 주세요.
4. 끝나면 **TBT 중지**를 누르고 일반 내비 안내를 다시 시작합니다.

> 가짜 경로 시험 중에는 순정 내비 안내도 꺼 두세요. 켜져 있으면 HUD 표시의 출처를 구분할 수 없습니다.

## 3. 결과 확인

- **휴대폰 로그 파일**: `/sdcard/Android/data/com.carrot.aaprobe/files/aaprobe-날짜-시각.jsonl`
  (앱 첫 화면에 정확한 경로가 표시됩니다). 이 파일을 전달해 주시면 분석합니다.
- **logcat**: 루팅/ADB 환경이면 `adb logcat -s AAProbe`
- **UDP 실시간 수신(선택)**: 앱에서 "로그를 UDP로도 전송"을 켜고 수신 IP/포트(기본 7799)를 저장합니다.
  받는 쪽(PC 또는 C4)에서 실행합니다.

```bash
python3 udp_listen.py --port 7799
```

### 로그에서 볼 항목

| kind | 의미 |
|---|---|
| `host` | AA 호스트 Car App API 레벨(3 미만이면 차량 데이터 API 사용 불가) |
| `subscribe` | 각 데이터 구독 성공/실패와 오류 내용 |
| `data` | 실제 값(`speed`, `mileage`, `energy_level`, `car_location`, `compass`, `accelerometer`, `gyroscope`, `model`, `energy_profile`, `toll`) |
| `tbt` | 보낸 회전 안내와 시각(HUD 사진·영상 시각과 맞춰 비교) |
| `nav_host_stop` | AA가 안내를 강제로 중단시킨 경우(예: 일반 내비 안내 재시작) |
| `lifecycle` | 앱 화면 상태(start/resume/pause/stop/destroy). 일반 내비로 전환한 뒤에도 `data`가 이어지는지 판단 |

## 4. 결과 해석

- **`car_location`이 SUCCESS** → 헤드유닛 GPS를 휴대폰에서 받을 수 있습니다. Carrot Navi 경로로 C4에 넘길 수 있습니다.
- **`speed` / `mileage` / `energy_level`이 SUCCESS** → 차량 속도·주행거리·연료 정보도 같은 방식으로 활용할 수 있습니다.
- **TBT 시험 중 HUD/계기판에 화살표가 표시됨** → Carrot용 AA 앱이 TMAP 경로를 이 방식으로 보내면,
  M-CAN 작업 없이 순정 HUD 안내를 쓸 수 있습니다.
- **표시되지 않음** → 이 헤드유닛은 AA 회전 안내를 HUD로 넘기지 않습니다. HUD를 쓰려면 M-CAN 경로만 남습니다.

## 5. 직접 빌드

JDK 17과 Android SDK(platform 34)가 필요합니다. Android Studio에서 이 폴더를 열거나 아래 명령을 실행합니다.

```bash
./gradlew assembleRelease
```

Windows에서 경로가 길거나 한글이 들어 있으면 AAPT2 데몬이 시작되지 않을 수 있습니다.
이때는 프로젝트를 짧은 ASCII 경로로 복사하거나 `subst`로 드라이브 문자를 붙여 빌드하세요.
