# 자동 레이더 진단 결정 기록.

- 사용자는 차량 안에서 C4 상태를 확인하거나 원격 작업을 안내할 수 없다. 실행 조건 확인과 결과 기록은 장치가 수행해야 한다.
- 기존 수동 차종 선택은 펌웨어 조회를 생략하므로 일반 캡처를 반복해도 ECU 식별정보가 자동으로 확보되지 않는다.
- 기존 종방향 동작과 설정을 유지한다. 진단 성공을 트랙 지원 또는 안전성 확인으로 해석하지 않는다.
- ECU 쓰기, 진단 세션 전환, 임의 DID 스캔, 레이더 활성화 및 Panda 안전 모드 변경은 범위 밖이다.
- 현대 주행용 안전 정책은 7D0의 tester-present 외 명령을 차단한다. 정책을 수정하지 않고 card의 get_car 직후, FirmwareQueryDone 이전에 이미 존재하는 ELM327 식별 단계에 연결했다.
- 신뢰할 수 있는 P단·정지 상태 1초를 최대 3초 동안 확인한다. 각 읽기의 전체 대기 한도는 0.5초이며 송신 직전과 수신 직후 조건을 다시 확인한다. P단 이탈·움직임은 즉시 중단한다.
- 장치 부팅 ID별 파일 예약으로 실패 후 card 재시작 시에도 재전송하지 않는다. 성공·거절·응답 없음·미실행 결과 모두 장면 파일 없이 독립 전송한다.
- 공통 레이더 판별·선행차 선택은 변경하지 않았다. 이 변경은 C4 수집 기능이 있는 carrot-wip-custom만 대상으로 한다. NAS 재생 엔진 재배포 및 다른 모델/기능 브랜치 변경은 범위 밖이다.
- Windows Python에는 capnp가 없어 실제 전송 계층 시험을 C4의 분리된 임시 디렉터리에서 수행했다. C4에서 실제 IsoTpParallelQuery의 다중 프레임/거절 처리를 포함한 40개 테스트가 통과했다. 송수신 콜백은 가상 CAN이며 실차 명령은 보내지 않았다.
- 기존 활성화 응답 시험 8개는 Windows에서 통과했다. 구문 검사 및 git diff --check도 통과했다. 이것은 실차 ECU 조회 성공이나 주행 안전성 검증을 뜻하지 않는다.
